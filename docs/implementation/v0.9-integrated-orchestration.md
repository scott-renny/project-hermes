# Project Hermes v0.9 Integrated Orchestration

Version 0.9 introduces the unified Project Hermes execution layer.

## Foundation

- Ordered execution from the portable workstation profile
- Component selection without violating dependency order
- Platform, file, module-command, and configuration preflight
- Audit and explicit apply modes
- Required and optional failure policies
- Persistent run state and bounded resume behavior
- Consolidated JSON and Markdown reports
- `WhatIf` support for apply and report operations
- Separate execution-success and desired-state compliance summaries
- State files are not written during `WhatIf` previews

The orchestrator composes existing module contracts. It does not duplicate component
configuration logic or silently broaden the settings managed by Project Hermes.

## Repository path safety

Persistent desktop and PowerShell settings resolve repository-owned paths from the
executing Project Hermes checkout. Apply those components only from the canonical
repository checkout, not from a temporary development worktree. Development
worktrees remain suitable for audits, preflight checks, plans, and `WhatIf` previews.
