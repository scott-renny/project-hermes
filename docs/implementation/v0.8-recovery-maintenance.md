# Project Hermes v0.8 — Recovery, Maintenance, and Reporting

## Scope

Project Hermes v0.8 unifies workstation configuration audits, drift summaries, Hermes backup health, maintenance evidence, and safe recovery coordination.

The Cyber Operations Center Engineering Program remains authoritative for infrastructure runbooks, incident playbooks, and operational governance. Hermes links to those procedures and produces supporting workstation evidence rather than duplicating them.

## First implementation slice

- Validate a maintenance policy.
- Run every enabled workstation component compliance test.
- Distinguish compliant, drifted, unavailable optional, and failed required components.
- Inventory standardized Hermes JSON backups.
- Detect invalid, stale, missing, and insufficient backups.
- Create one consolidated maintenance report.
- Export UTF-8 JSON and Markdown evidence.
- Preserve `WhatIf` support for filesystem writes.

## COC operational references

- RB-011 — Backup Job Failure
- RB-012 — Repository Integrity Validation
- RB-013 — File Restore
- RB-014 — Full-System Restore
- PB-003 — Ransomware Response
- PB-004 — Backup Repository Compromise

## Deferred until the audit contract is proven

- Automated drift repair.
- Backup deletion and retention cleanup.
- Multi-component restore orchestration.
- Scheduled maintenance tasks.
- Remote submission of sanitized evidence.

These operations can change or remove system state and require separate preview, confirmation, rollback, and validation contracts.
